月底翻账单，订阅费照扣，卡里又多出一笔 API 支出——这是不少 Claude Code 用户最近碰到的场景。明明开的是 Pro 或 Max，为什么还会冒出按 token 计费的费用？钱从哪儿扣的，能不能彻底关掉？

## 先分清两套计费系统：订阅和 API 是两个独立的钱包

Claude Code 本身不单独收费，它包含在 Claude 的付费订阅里。但 Anthropic 同时维护着两套互不相通的计费系统，超额收费的混乱几乎都从这里开始。

第一套是订阅。Pro 每月 20 美元，Max 5x 每月 100 美元，Max 20x 每月 200 美元。网页端聊天和 Claude Code 共用同一个额度池，限制分两层：5 小时会话窗口加每周限额，Max 用户还有一个针对 Fable 模型的独立每周限额。

第二套是 API。在 Claude Console 里充值、按 token 扣费，和订阅完全无关。官方文档给企业用户的参考成本是：平均每个开发者每个活跃日约 13 美元，每月 150 到 250 美元，90% 的用户能控制在每天 30 美元以内。

这是平均值。走 API 时，价格取决于你用哪个模型：

| 模型 | 输入（美元/百万 token） | 输出（美元/百万 token） | 缓存读取 |
| --- | --- | --- | --- |
| Fable 5.1 | 10 | 50 | 0.25 |
| Opus 5.5 | 4 | 20 | 0.20 |
| Sonnet 5 | 2 | 10 | 0.20 |
| Haiku 4.5 | 1 | 5 | 0.10 |

Claude Code 从 9 月 22 日起默认使用 Opus 5.5。代理式编码任务的 token 消耗远超普通聊天——一次“重构认证模块并补上测试”级别的任务，烧掉的 token 可能顶得上 50 轮普通对话。用 API 方式跑这类任务，账单涨得快并不奇怪。

## 超额收费最常见的三个来源

### 陷阱一：环境变量里的 ANTHROPIC_API_KEY

这是官方帮助文档明确警告的头号原因。只要系统里设置了 ANTHROPIC_API_KEY 这个环境变量，Claude Code 就会优先用它做身份验证——走 API 按量计费，订阅额度一动不动，账单却在涨。

很多人是当初配置别的工具时顺手设的，事后自己都忘了。排查方法：在 Claude Code 里输入 /status，看当前认证走的是订阅账号还是 API key；/usage 显示额度消耗进度。

处理方式也直接：移除这个环境变量，用 /logout 完全退出后重新登录，登录时选择你的 Claude 订阅账号。如果当初是用 Console 的 API key 登录的，直接在 Claude Code 里运行 /login 就能切换到订阅。

### 陷阱二：到限额后顺手点了 API credits

订阅额度用完时，Claude Code 会给出继续使用的选项。如果账号里绑定了 Console 凭证，就可以选择用 API credits 续命，按标准 API 费率计费。

这个选项本身需要主动开启，问题出在两个环节。一是弹窗出现时人多半正在赶工，没细看就点了确认。二是 Console 里如果开了 auto-reload，余额不足时会自动从绑卡扣款充值——超额就从“手动确认”变成了“自动扣款”。

想严格待在订阅额度内：到限额时拒绝 API credit 选项，等额度重置，平时用 /status 盯剩余额度。想彻底不看到这类提示：在终端执行 claude logout，再用 claude login 登录，全程只用订阅账号凭证，不要添加任何 Console 凭证。auto-reload 的开关在 Claude Console 账户设置里管理，不在 Claude Code 里。

### 陷阱三：没人盯着的子代理和批量任务

前两个坑是“不明不白被扣钱”，这个是“明明白白，但没想到这么多”。

/batch 命令和多代理编排会把一个任务拆成 5 到 30 个独立单元并行执行，效率确实高。但任务跑在最贵的模型上、又无人值守时，成本会彻底失控。GitHub 上有公开记录的案例：一次 TypeScript 校验任务并行跑起 49 个子代理，持续 2.5 小时，产生估计 8,000 到 15,000 美元的 token 费用；一个金融服务团队把 23 个子代理留在后台过夜分析代码，三天后收到 47,000 美元的 API 账单。

还有个更容易忽略的细节：prompt cache。有用户把会话闲置 1 小时 49 分钟后恢复，缓存早已过期，586,000 个 token 被完整重新处理。缓存读取本身便宜（每百万 token 0.10 到 0.25 美元），但缓存失效后的全量重读按原价计费。

跑无人值守任务前，先设好 token 预算和会话上限。桌面端的预算控制和命令行的 --max-turns 参数就是干这个用的。

## 彻底关掉超额扣费的操作清单

照着做一遍，超额收费的入口基本就堵死了：

1. 排查环境变量。确认系统里没有 ANTHROPIC_API_KEY，有就移除，然后重启终端。
2. 重新登录。/logout 完全退出，运行 claude update 更新，重启终端后用 claude login 登录，只选订阅账号凭证。
3. 到限额时拒绝 API credit 选项，等额度自然重置。
4. 去 Claude Console 检查 auto-reload 设置，不需要就关掉。
5. 日常用 /status 确认认证方式，用 /usage 看额度进度。
6. 无人值守任务必须设预算上限和 --max-turns，子代理别默认挂在最贵的模型上。

> 核心原则只有一条：让 Claude Code 的登录凭证只来自订阅账号。只要不掺入 Console API 凭证，就基本不存在“订阅之外被扣钱”的通道。

## 几个高频问题

**怎么确认 Claude Code 现在走的是订阅还是 API？**

输入 /status，看认证信息里显示的是订阅账号还是 API key；/usage 显示当前额度的消耗进度。账单出现意外时，先查这两个命令。

**已经产生了意外的 API 扣款怎么办？**

先按上面的清单切断计费入口：移除环境变量、重新登录、关闭 auto-reload。然后再联系官方支持说明情况——官方文档明确把 ANTHROPIC_API_KEY 列为“导致 API 计费而非使用订阅”的原因，这类沟通有据可依，能否退款则因个案而异。

**每周限额具体是多少？**

官方没有公布固定数字，消耗速度取决于模型、上下文大小和任务复杂度。社区里有 Pro 用户报告过半小时烧完整个 5 小时窗口（多仓库、Opus 加 Sonnet 的重度用法）；也有 Max 20x 用户在工作日第一天就用掉 72% 的周额度。9 月下旬官方随 Opus 5.5 上调过 5 小时限额，但重度用户触顶仍是常态。更早的 3 月还出过一轮额度异常消耗风波，官方确认了两个已修复的 prompt caching 故障，高峰期限速则作为产品决策保留了下来。

**usage credits 打开后还能关吗？**

可以，在设置的 Usage 里管理。这个功能是主动开启的，不开就永远不会产生额外扣费——到限额时 Claude 直接暂停，等额度重置。真正要防的是 auto-reload：它由 Console 控制，只在 API credits 生效时才自动充值。

## 写在最后

Claude Code 的超额收费不是玄学，来源就三个：环境变量劫持认证、限额后的 API credits、没人看管的批量任务。把登录凭证收敛到订阅账号、关掉 auto-reload、给自动化任务设上限，这三件事做完，账单基本就回到订阅费本身。
